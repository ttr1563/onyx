Linux command safety

A last line of defense for server commands.

Onyx detects risky operations, blocks them before execution, and requires approval from a separate TOTP authenticator.

Quick start

Small surface. Explicit control.

Install from the signed DNF or APT repository, Homebrew, or an immutable Git release tag. Windows users run the Linux build inside WSL 2. Then enroll any RFC 6238-compatible authenticator.

sudo rpm --import https://ttr1563.github.io/onyx/rpm/RPM-GPG-KEY-ONYX
sudo dnf install https://ttr1563.github.io/onyx/rpm/onyx-release-1-1.noarch.rpm
sudo dnf install onyx

onyx init --account production-web-01
sudo onyx policy init --account production-policy-admin
onyx run -- systemctl status nginx

Approval flow

Nothing dangerous runs while you decide.

  1. DetectOnyx evaluates the executable and arguments.
  2. DenyA matching operation receives an event ID and exit code 77.
  3. ApproveYou inspect the event and enter a TOTP code without terminal echo.
  4. Retry onceThe exact command can run once within 30 seconds.

Custom policy

Root-owned rules for your environment.

Initialize the system policy once. Adding or removing a rule then requires root and the separate policy-administrator TOTP.

sudo onyx policy init --account production-policy-admin
sudo onyx policy add \
  --id production-terraform \
  --executable terraform \
  --argument-contains apply \
  --argument-contains production \
  --risk critical \
  --reason "production change"

Scope

What v0.1 does not cover.

The root-owned policy prevents normal-user rule changes. Onyx does not cover commands that bypass onyx run, root-level bypass, state-owner changes to events or permits, or physical-presence verification.
