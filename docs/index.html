Linux command safety

A last line of defense for server commands.

Osmanthus denies selected destructive filesystem operations below protected directories, records local evidence, and uses TOTP for scoped maintenance.

Kernel boundary

Linux denies the protected resource operation before the target changes.

Scoped maintenance

Quick start

Small surface. Explicit control.

The enforced daemon is currently a development branch. Build and validate it locally before package publication, then enroll an RFC 6238-compatible policy-administrator authenticator.

git clone https://github.com/ttr1563/osmanthus-shell.git
cd osmanthus-shell
git checkout feature/enforced-shell-monitoring
cargo build --release --locked
# Install all three binaries and the service; see Install.

sudo osmanthus policy init --account production-policy-admin
sudo systemctl enable --now osmanthusd
sudo osmanthus policy protect add --path /srv/production --action delete --action rename

Enforcement flow

Normal commands, protected resources.

  1. ObserveEnrolled UIDs produce exec and optional PTY transcript events.
  2. MatchThe kernel matches target ancestry and operation class.
  3. DenyA protected operation fails before changing its target.
  4. MaintainA TOTP-authenticated path/action/cgroup lease expires automatically.

Custom policy

Root-owned rules for your environment.

Initialize the system policy once. Protect only the directories and destructive operation classes that need a hard boundary. Every later change requires root and the separate policy-administrator TOTP.

sudo osmanthus policy protect add --path /srv/production \
  --action delete \
  --action rename \
  --action truncate \
  --action write

sudo osmanthus maintenance grant \
  --path /srv/production/releases/old \
  --action delete --for 5m

sudo osmanthus policy maintenance set \
  --default 15m --maximum 12h

Data boundary

Protect integrity first. Treat access separately.

Opt-in write protection can make release or credential directories immutable. Database reads, credentials, and outbound destinations require identity-aware read and network policies; they are a separate planned layer rather than command-name matching.

sudo osmanthus maintenance pause \
  --path /srv/production/database \
  --for 8h

The lease is bound to the authenticated caller's kernel cgroup; another login cgroup remains blocked.

Scope

What Osmanthus does not cover.

Osmanthus does not contain Linux root or a compromised kernel/boot chain. TOTP adds independent approval and delay; it is not proof of physical presence. Native Windows Server enforcement remains unimplemented.
