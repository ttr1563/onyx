Installation

Install the complete enforcement stack.

The daemon, BPF programs, supervised shell, service unit, and CLI are one operational unit.

Release status

Not released yet: the public Onyx v0.1.3 DNF, APT, Homebrew, and Git-tag packages are the earlier explicit-wrapper product. They are not Osmanthus packages and do not contain this enforced backend.

The commands below build the current development branch for evaluation. A new version and signed repositories will be documented only after package-level acceptance and release approval.

Linux prerequisites

test -r /sys/kernel/btf/vmlinux
grep -qw bpf /sys/kernel/security/lsm
mountpoint /sys/fs/bpf
systemctl --version
sudo bpftool feature probe kernel | grep -A200 'program type lsm' | grep -w bpf_loop

Building additionally requires Rust 1.91+, clang/LLVM, libelf, zlib, libbpf headers, and a C toolchain. The final package embeds its BPF object; clang is not a runtime dependency.

Build from Git

git clone https://github.com/ttr1563/osmanthus-shell.git
cd osmanthus-shell
git fetch origin
git checkout feature/enforced-shell-monitoring
cargo build --release --locked

sudo install -m0755 target/release/osmanthus /usr/bin/osmanthus
sudo install -m0755 target/release/osmanthusd /usr/bin/osmanthusd
sudo install -m0755 target/release/osmanthus-shell /usr/bin/osmanthus-shell
sudo install -m0644 ops/systemd/osmanthusd.service /usr/lib/systemd/system/osmanthusd.service
sudo install -m0644 ops/logrotate/osmanthus /etc/logrotate.d/osmanthus
sudo install -D -m0644 ops/ssm/osmanthus-session.json /usr/share/osmanthus/ssm/osmanthus-session.json

A mutable development branch is suitable only for evaluation. Production installation must use an immutable signed release artifact.

Build local packages

scripts/build-rpm.sh 0.1.3 dist/rpm
scripts/build-deb.sh 0.1.3 dist/deb

These commands create local artifacts only; they do not publish or sign a repository. The deb builder produces amd64 on native Linux x86-64 and arm64 on native Linux ARM64; it does not cross-package. The development package currently has the same manifest version as public v0.1.3, so it must not overwrite or masquerade as that release. Version selection is a release decision.

Initialize and verify

sudo osmanthus policy init --account production-policy-admin
sudo systemctl daemon-reload
sudo systemctl enable --now osmanthusd
osmanthus daemon status

sudo osmanthus policy protect add --path /srv/production \
  --action delete --action rename --action truncate
sudo osmanthus policy monitor add 1001 --shell /bin/bash

Use a disposable directory for the first boundary test and keep a console/recovery path before changing a login shell. Normal filesystem enforcement does not require osmanthus run.

Authenticator rotation

While the current TOTP authenticator is available, run sudo osmanthus policy auth rotate to issue a replacement QR/URI. The previous secret becomes invalid immediately. Loss of every enrolled copy requires restoration from a tested root-restricted backup; direct file editing is not a recovery method.

Remote entry points

OpenSSH and local logins for an enrolled account enter through osmanthus-shell. AWS SSM can skip the login shell; use the repository's custom Session document procedure. Restrict IAM so operators can start only that document and cannot update it.

Migration, rollback, and uninstall

Osmanthus does not import legacy Onyx state. Restore any account using /usr/bin/onyx-shell and decommission /sys/fs/bpf/onyx with the matching Onyx binary before installation; Osmanthus refuses to start while the old kernel backend remains.

Same-ABI BPF upgrades use replacement links and pin promotion. An incompatible ABI is rejected while the old enforcement remains attached; rollback to the previous package or use an authenticated maintenance/decommission/fresh-attach window.

sudo osmanthus policy monitor remove 1001
sudo osmanthus daemon decommission
sudo dnf remove osmanthus        # or: sudo apt-get remove osmanthus

Uninstall refuses while Osmanthus BPF pins or managed login shells remain. Policy, state, and audit evidence are retained. Review the operations runbook before rollback or removal.
