# Onyx v0.1.3

Onyx v0.1.3 makes authenticator enrollment practical in a normal terminal
window. A representative production label now renders as 41 columns by 21
rows instead of 114 columns by 57 rows, and the QR is printed last so scrolling
does not push part of it out of a 24-line camera view.

## Compact enrollment QR

- Unicode half-block cells encode two vertical QR modules per terminal row.
- Low error correction is used for a clean local screen where damaged modules
  are not expected.
- A compact terminal border remains around the code for camera separation.
- Long custom issuer or account labels can still increase the QR version and
  its dimensions.

The provisioning URI retains the secret, account label, and issuer. Optional
parameters are omitted when they equal the standard defaults: SHA-1, six
digits, and a 30-second period.

## Compatibility

The state schema, root-owned system policy, command-bound approval flow, audit
format, and package paths are unchanged. Existing state does not require a
migration. The QR change affects only a newly displayed enrollment code; it
does not rotate or modify an already enrolled TOTP secret.

## Security boundary

Onyx remains an explicit Linux command wrapper. Commands that do not pass
through `onyx run -- ...` remain outside its protection boundary. Root and a
fully compromised state owner can bypass local controls, and local-only audit
records are not tamper-proof against privileged access. Review `SECURITY.md`
before production use.
