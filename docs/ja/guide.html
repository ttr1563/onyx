Onyxは何をしているのか。

コマンド実行前の判定、一度限りの承認、ローカル証跡、そして運用時に守るべき限界を説明します。

保護モデル

Onyx v0.1は明示的なコマンドラッパーです。自動処理または運用者がonyx run -- <command>を実行すると、Onyxは子プロセスを作成する前に引数列を評価します。このラッパーを経由しないコマンドは横取りも監視もしません。

1. 受付onyx run -- ...
2. 判定組込みルールと追加ルール
3. 決定即時許可または遮断イベント作成
4. 実行permitを消費してからプロセス作成
5. 監査秘匿値を除いたJSONL追記

実行前はfail-closed：必要な状態や実行前監査記録を安全に書けなければ、保護対象コマンドを開始しません。ただし、実行済みコマンドは完了ログの書込み失敗によって取り消せません。

安全な経路と危険な経路

判定Onyxの処理利用者から見た結果
ルール一致なし許可記録を書き、子プロセスを開始します。子プロセスの終了コードをそのまま返します。
危険ルール一致、permitなしpending eventを作り、子プロセスを開始しません。終了コード77、event ID、該当rule IDを返します。
危険ルール一致、完全一致permitありpermitを原子的に消費してから子プロセスを開始します。承認したコマンドを一度だけ実行できます。
状態・排他・監査の失敗子プロセスを開始せずエラーにします。管理者による原因確認が必要です。

承認は一つのコマンドへ厳密に結び付きます

危険なコマンドを拒否すると、Onyxは各引数のバイト長と値を順番どおりにSHA-256へ入力します。引数境界も区別するため、ある引数列への承認を、表記やオプションを変えた別コマンドへ流用できません。

遮断pending event、有効10分
確認redact済みコマンドとrule
TOTP6桁、再利用・失敗回数を検査
Permit完全一致digest、有効30秒
消費済み子プロセス開始前に削除

TOTPは共有秘密方式です。登録済み認証器を持たない操作主体に時間的な壁を作れますが、物理的な在席証明ではありません。Onyx状態の所有者またはrootとして動くコードは、サーバー側seedを読めます。ハードウェア署名を使う非対称承認は将来の特権broker構想であり、現行版の機能とは主張しません。

ポリシーと解釈の難しいコマンド

組込みポリシーは、再帰的削除、filesystem初期化、raw device書込み、shutdown、権限wrapper、shell文字列、破壊的なfind、root全体の権限変更、秘密情報らしき転送、decodeとevalの組合せなど、少数の監査しやすいパターンを対象にします。CLIから追加するsite ruleは遮断範囲を広げる方向にだけ働きます。

Onyxは意味解析型のmalware検出器ではありません。shell文字列、interpreter、alias、難読化payload、同等のsystem callは意図を隠せます。そのため安全な操作でも保守的に承認を求める場合があり、wrapper外の操作は見えません。

状態とローカル証跡

rootは/var/lib/onyx、一般ユーザーはXDG state directoryを使います。directoryは0700、機密fileは0600です。symlinkと想定外のfile種別を拒否し、JSON更新は同一directoryの一時file、fsync、rename、親directoryのfsyncで行います。

onyx/
├── .lock
├── audit.jsonl
├── auth-state.json
├── config.json
├── policy.json
└── events/<event-id>.json

監査記録にはUTC時刻、action、event ID、command digest、redact済み概要、該当rule ID、必要な終了状態を含めます。stdout、stderr、環境変数、TOTP seed、入力コードは記録しません。ただしrootはローカル証跡を変更できます。改ざん耐性が必要なら既存collectorから外部保存してください。

導入・運用フロー

  1. 署名済みRPMを導入し、実際に利用する制約付きOS identityでOnyxを初期化します。
  2. 時刻同期、権限、安全な実行、非実行の遮断checkを確認します。
  3. 保護したいautomationの入口をonyx run -- ...へ変更します。
  4. 遮断の反復、承認失敗、disk容量、時刻同期、wrapperを迂回する経路を監視します。
  5. 別管理の復旧経路を残し、incident作業前に必要な状態と証跡を保全します。

本番利用前に運用runbook、architecture、security policyを確認してください。
