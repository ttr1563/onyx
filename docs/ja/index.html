Linux command safety

サーバー操作に、最後の防御線を。

Onyxは危険な操作を実行前に検知・遮断し、別端末のTOTP認証器による承認を要求します。

まず遮断

危険なコマンドは子プロセスが開始する前に拒否します。

一度だけ承認

短時間の許可を一つのコマンドダイジェストへ結び付け、一度だけ消費します。

秘匿値を除いたJSONL記録を、既存のログ転送基盤から利用できます。

クイックスタート

小さな構成で、明示的に守る。

Amazon Linux 2023では、署名付きOnyxリポジトリを一度登録するとDNFから導入・更新できます。その後、RFC 6238互換の認証アプリを登録します。

sudo rpm --import https://ttr1563.github.io/onyx/rpm/RPM-GPG-KEY-ONYX
sudo dnf install https://ttr1563.github.io/onyx/rpm/onyx-release-1-1.noarch.rpm
sudo dnf install onyx

onyx init --account production-web-01
sudo onyx policy init --account production-policy-admin
onyx run -- systemctl status nginx

承認フロー

判断が終わるまで、危険な操作は動きません。

  1. 検知実行ファイルと引数を評価します。
  2. 拒否該当操作へイベントIDと終了コード77を返します。
  3. 承認イベントを確認し、画面に表示しない形でTOTPコードを入力します。
  4. 一度だけ再実行同一コマンドを30秒以内に一度だけ実行できます。

保護境界

Onyx v0.1は明示的なラッパーであり、ホスト全体を強制保護するものではありません。

root所有のsystem policyにより、保護対象ユーザーは追加ルールを変更できません。ただしonyx run外は保護されず、rootはガードを無効化でき、状態所有者は実行event、permit、実行承認用TOTP seedを操作できます。
