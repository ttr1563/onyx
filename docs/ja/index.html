Linux command safety

サーバー操作に、最後の防御線を。

Onyxは危険な操作を実行前に検知・遮断し、別端末のTOTP認証器による承認を要求します。

クイックスタート 導入方法 仕組みを読む ソースを見る
01

まず遮断

危険なコマンドは子プロセスが開始する前に拒否します。

02

一度だけ承認

短時間の許可を一つのコマンドダイジェストへ結び付け、一度だけ消費します。

03

証跡はローカルに

秘匿値を除いたJSONL記録を、既存のログ転送基盤から利用できます。

クイックスタート

小さな構成で、明示的に守る。

署名付きDNF/APTリポジトリ、Homebrew、または固定したGit release tagから導入できます。WindowsではWSL 2内のLinux版を利用します。その後、RFC 6238互換の認証アプリを登録します。

sudo rpm --import https://ttr1563.github.io/onyx/rpm/RPM-GPG-KEY-ONYX
sudo dnf install https://ttr1563.github.io/onyx/rpm/onyx-release-1-1.noarch.rpm
sudo dnf install onyx

onyx init --account production-web-01
onyx run -- systemctl status nginx

承認フロー

判断が終わるまで、危険な操作は動きません。

  1. 検知実行ファイルと引数を評価します。
  2. 拒否該当操作へイベントIDと終了コード77を返します。
  3. 承認イベントを確認し、画面に表示しない形でTOTPコードを入力します。
  4. 一度だけ再実行同一コマンドを30秒以内に一度だけ実行できます。

カスタムポリシー

環境固有の承認ルールを追加。

実行ファイル名と必須の引数断片を指定できます。追加ルールは組込みポリシーと併用され、変更は監査ログへ記録されます。

onyx policy add \
  --id production-terraform \
  --executable terraform \
  --argument-contains apply \
  --argument-contains production \
  --risk critical \
  --reason "production change"

対象外

v0.1で担保しない範囲。

onyx runを経由しない操作、rootによる迂回、物理的な本人確認は担保しません。
