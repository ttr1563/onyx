導入

強制保護一式を導入する。

daemon、BPF program、監査shell、systemd unit、CLIを一つの運用単位として扱います。

公開状況

現時点では未releaseです：公開済みOnyx v0.1.3のDNF・APT・Homebrew・Git tagは旧明示wrapper製品です。Osmanthus packageではなく、この強制backendを含みません。

以下は開発branchを評価用にbuildする手順です。新versionと署名済みrepositoryは、package単位の受入確認とrelease承認後に案内します。

Linux前提条件

test -r /sys/kernel/btf/vmlinux
grep -qw bpf /sys/kernel/security/lsm
mountpoint /sys/fs/bpf
systemctl --version
sudo bpftool feature probe kernel | grep -A200 'program type lsm' | grep -w bpf_loop

buildにはRust 1.91以降、clang/LLVM、libelf、zlib、libbpf header、C toolchainも必要です。完成packageはBPF objectを内包し、runtimeではclangを必要としません。

Gitからbuild

git clone https://github.com/ttr1563/osmanthus-shell.git
cd osmanthus-shell
git fetch origin
git checkout feature/enforced-shell-monitoring
cargo build --release --locked

sudo install -m0755 target/release/osmanthus /usr/bin/osmanthus
sudo install -m0755 target/release/osmanthusd /usr/bin/osmanthusd
sudo install -m0755 target/release/osmanthus-shell /usr/bin/osmanthus-shell
sudo install -m0644 ops/systemd/osmanthusd.service /usr/lib/systemd/system/osmanthusd.service
sudo install -m0644 ops/logrotate/osmanthus /etc/logrotate.d/osmanthus
sudo install -D -m0644 ops/ssm/osmanthus-session.json /usr/share/osmanthus/ssm/osmanthus-session.json

可変な開発branchは評価専用です。本番導入ではimmutableな署名済みrelease artifactを使用します。

local packageを生成

scripts/build-rpm.sh 0.1.3 dist/rpm
scripts/build-deb.sh 0.1.3 dist/deb

この操作はlocal artifactを作るだけで、repositoryへの公開や署名は行いません。deb builderはnative Linux x86-64でamd64、native Linux ARM64でarm64を生成し、cross packageは行いません。開発packageは公開v0.1.3と同じmanifest versionのため、公開物を上書きしたり同じreleaseとして配布してはいけません。versionはrelease時に決定します。

初期化と確認

sudo osmanthus policy init --account production-policy-admin
sudo systemctl daemon-reload
sudo systemctl enable --now osmanthusd
osmanthus daemon status

sudo osmanthus policy protect add --path /srv/production \
  --action delete --action rename --action truncate
sudo osmanthus policy monitor add 1001 --shell /bin/bash

最初の境界testは使い捨てdirectoryで行い、login shell変更前にconsole・復旧経路を確保します。通常のfilesystem保護にosmanthus runは不要です。

認証器rotation

現在のTOTP認証器を利用できる間にsudo osmanthus policy auth rotateを実行すると、新しいQR/URIを発行できます。旧secretは直ちに無効になります。登録済み認証器をすべて失った場合は、検証済みのroot専用backupから復元します。fileの直接編集は復旧手順にしません。

remote接続

登録accountのOpenSSH・local loginはosmanthus-shellを通ります。AWS SSMはlogin shellを迂回できるため、repositoryの専用Session document手順を使用します。operatorがそのdocumentだけを開始でき、更新はできないようIAMを制限します。

移行・rollback・削除

Osmanthusは従来Onyxのstateを自動importしません。導入前に/usr/bin/onyx-shellを使用するaccountを復元し、対応するOnyx binaryで/sys/fs/bpf/onyxをdecommissionしてください。旧kernel backendが残る間はOsmanthusの起動を拒否します。

同一ABIのBPF更新はreplacement linkとpin昇格を使います。非互換ABIは旧enforcementをattachしたまま拒否されるため、旧packageへrollbackするか、認証付きの保守・decommission・fresh attachを行います。

sudo osmanthus policy monitor remove 1001
sudo osmanthus daemon decommission
sudo dnf remove osmanthus        # または: sudo apt-get remove osmanthus

OsmanthusのBPF pinまたは管理login shellが残る間、uninstallは拒否されます。policy・state・audit証跡は保持します。rollback・削除前に運用runbookを確認してください。
